3] Synapse — Verified AI Data Workspace
 Personal project · built solo, backend to frontend · Apr 2026 – present

One-line description
An AI workspace where you ask your databases and documents questions in plain English. It checks every number a second, independent way before you see it, charts the result, and sends it to Slack, Gmail or Drive.

Project description (short, for resume)
A production AI agent that converts natural language into SQL across SQLite, MySQL and CSV/Parquet in one query using DuckDB. A trust layer re-checks each answer with independent queries and labels it Verified, Verified with caveats, or Don't trust this yet. It also builds verified dashboards, does document Q&A with page citations and runs deep web research. It has 47 actions across Gmail, Drive, Docs, Sheets and Slack, and nothing is sent or changed without the user's approval.

Project description (long, for portfolio)
AI tools that write SQL usually fail without any warning. A JOIN can double-count rows and inflate revenue, or orders with no matching customer can quietly drop out of a total. Synapse is built around catching those mistakes. It answers questions over your existing databases and files without a data warehouse. It then re-checks the headline number a second, independent way and tells you plainly when not to trust it. From there it builds charts and dashboards and delivers them where the decision happens, in Slack, Gmail or Drive. A confirmation step sits in front of anything that sends, writes or deletes.

Tech stack
Layer	Technologies
Backend	Python, FastAPI (async), SSE streaming, WebSockets, SQLAlchemy, Alembic
AI agents	LangGraph (think → act → observe loop), MCP-style tool layer, intent classification, model routing per question

Data	DuckDB (combines SQLite + MySQL + CSV/Parquet in one query), sqlparse

Key features
NL2SQL across data sources. Combine SQLite, MySQL and CSV/Parquet in one statement through DuckDB. Schema linking shows the model real example values from each column. On large schemas, a retrieval pass picks only the relevant tables.
Trust layer. After answering, Synapse runs a second, independent set of checks:
Metric resolution: was the metric taken from the defined glossary or guessed from a column name?
Cross-source reconciliation: the total is calculated a second way, and the answer is blocked if the two disagree.
Fan-out and completeness: orphan or duplicate rows are reported with the row count and their effect on the total.
Safe writes. INSERT, UPDATE, DELETE and DDL statements are classified by rules using sqlparse, not by the model. Destructive SQL pauses the agent and shows the exact SQL, the risk level and the estimated number of affected rows. High-risk operations require typing a keyword to confirm.
Governed semantic layer. A business glossary plus certified metrics, so a term like "Net Revenue" is defined once and calculated the same way every time. Every query is written to an audit trail.
Charts with a critic. The chart type is chosen from the shape of the data. A second "critic" stage rejects misleading visuals, such as a pie chart of long-tailed data or an ID column charted as a measure.
Dashboards.
Every query result gets an automatic mini-dashboard.
Asking for a whole-database overview makes the LLM plan the questions; each panel is a real, checked query.
A 2D/3D Chart Studio for manual exploration.
Pixel-perfect PDF export of what's on screen.
AI agent with 47 actions. Connected to Gmail, Drive, Docs, Sheets and Slack, so one sentence can run a whole workflow: query → verify → chart → PDF → post to Slack. Anything that sends or changes something needs human approval. Before the agent can say "done", a verifier confirms the API call actually happened.
Document RAG.
Upload PDF, DOCX, XLSX, PPTX, CSV, images and more, up to 100 MB each.
Hybrid search with reranking.
Strict per-document isolation: only the documents you tick are searched.
Citations jump to the source page.
A different retrieval strategy for each type of question.
Live ingestion progress over WebSocket.
Deep research and scraping. The loop runs plan → parallel search (Tavily + Exa) → full-page read (Firecrawl) → critic loop → answer with citations. Scraped websites become spreadsheets that are automatically registered as data sources you can query.
Production reliability.
Background ingestion on a queue.
A self-healing index: documents marked as indexed but holding no vectors are re-ingested on startup.
Encrypted credentials and per-key cooldowns.
An evaluation harness that scores SQL by whether its results match, not by comparing text.

Switchboard AI — Local Multi-Model LLM Gateway
Personal open-source project · built solo · Sep 2026 · Python, FastAPI

One-line description
A local, OpenAI-compatible API gateway that puts 17 LLMs (Claude, Gemini, GPT-OSS) behind one address. It routes each request to the best-value model, falls back automatically when a model fails, and lets you stream, run multiple models on one question, or run agent tasks. All of this goes through one API.

Project description (short, for resume)
A FastAPI server that puts the official Claude Code and Antigravity CLIs behind one OpenAI-compatible REST API. It offers 29 model options (17 distinct LLMs) and smart routing across them. A pool of already-running CLI processes keeps replies fast, answers stream live, failing models are swapped out automatically, and agent tasks can work on local files. Existing OpenAI SDK code works by changing only the base URL.

Project description (long, for portfolio)
Every AI provider has its own API, its own format and its own failure modes. Teams also tend to send every request, even a greeting, to the most expensive flagship model. Switchboard sits between the application and the models as a single gateway. Clients send one standard OpenAI-format request. Switchboard classifies the task, picks the model and how much "thinking" it gets, and switches to the next candidate if a model is rate-limited or down. Every response reports its tokens and cost. Under the hood it manages long-running CLI processes, converts each provider's output into one common event stream, and protects the local server against cross-site and DNS-rebinding attacks.

Tech stack
Layer	Technologies
Backend	Python, FastAPI, asyncio, Server-Sent Events, Pydantic, .env config
LLM providers	Claude Code CLI (12 Claude models), Antigravity CLI (Gemini 3.x, GPT-OSS 120B), optional Anthropic API (pay per token)
API compatibility	OpenAI-compatible /v1/chat/completions and /v1/models
Process management	Subprocess pool exchanging JSON over stdin/stdout, already-running spare processes, a concurrency queue, crash recovery
Auth automation	Hidden-terminal driving with pyte for Google OAuth sign-in from the web UI
Frontend	A self-contained web chat UI (HTML/JS) with model picker, status page and cost details
Deployment	Docker, docker-compose, an AWS EC2 install script with systemd, CloudFront keep-alive for long streams; runs on Linux, macOS and Windows
Key features
One OpenAI-compatible API
29 model options covering 17 distinct LLMs: 12 Anthropic, 4 Google and 1 OpenAI.
Existing OpenAI SDK code works by switching the base URL to localhost:8000/v1.
Smart routing with three Auto modes
auto classifies each request into one of 7 types (chat, writing, creative, code, reasoning, research, long), scores its difficulty from 1 to 5, and picks the model and thinking level. It falls back through up to 3 candidates if one fails.
auto-orchestrate plans, splits the task into 2–5 subtasks that run in parallel, has a model from a different family review the results, then writes the answer.
auto-ensemble gets independent answers from Claude, Gemini and GPT-OSS and merges them.
Already-running processes for fast replies
One CLI process per conversation, so only new messages are sent.
Spare processes are pre-started and refreshed every 30 minutes.
Idle conversations are closed after 15 minutes.
Concurrency is capped (6 Claude / 4 Gemini requests at once) with a queue for the rest.
A crashed process is replaced and the conversation is replayed, so nothing is lost.
Streaming
Server-Sent Events with one common event format: session, text, tool_use, tool_result, notice, result, done.
A 25 ms pacing layer evens out bursty output so text flows smoothly.
Keep-alive pings stop AWS CloudFront from cutting off long answers.
Automatic failover. Rate limits (429) and "no capacity" errors (503) switch to the next model with no error shown to the user. Errors that happen after part of the answer has already streamed show a warning instead.
Agent mode for local files.
Tasks run inside one approved folder, with an allowlist of tools.
Shell commands are off by default.
Each tool step streams live, and a task can be resumed later.
Web UI. Chat, a model picker, account and quota status, cost details per response, and Google sign-in done entirely in the browser.
Security
Listens on 127.0.0.1 only by default.
Blocks requests from other origins and from unknown host names (protection against DNS rebinding).
Optional Bearer API key.
Agent file access is limited to approved folders.
Credentials stay in the official CLIs' own stores, never in Switchboard.
Works across platforms. Automatically finds the CLIs (newest version wins) on Windows, macOS and Linux. A first-run installer and one-command deploy to EC2 are included.
